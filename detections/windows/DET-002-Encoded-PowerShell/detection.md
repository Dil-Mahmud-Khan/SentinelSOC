# Detection

## Threat Description
Attackers frequently abuse PowerShell because it is a trusted, built-in Windows administration tool. One common technique is using the `-EncodedCommand` parameter to execute Base64-encoded commands, making malicious activity more difficult to read, detect, and investigate.

Encoded PowerShell commands are commonly used by malware, ransomware operators, red teams, and penetration testers to evade basic command-line monitoring, obfuscate payloads, and execute malicious scripts directly in memory.

Detecting the use of encoded PowerShell commands helps security teams identify suspicious execution activity at an early stage before an attacker establishes persistence, steals credentials, or moves laterally within the environment.
## Detection Objective
The objective of this detection is to identify PowerShell processes that execute Base64-encoded commands using the `-EncodedCommand` or `-enc` parameter.

The detection enables SOC analysts to quickly identify suspicious PowerShell activity, investigate the executed command, determine whether it is malicious or legitimate, and initiate the appropriate incident response procedures.

## Attack Flow
1. Attacker launches PowerShell.
2. A Base64-encoded command is supplied using the `-EncodedCommand` parameter.
3. PowerShell decodes and executes the command.
4. Windows generates process creation logs.
5. Sysmon records Event ID 1.
6. The Wazuh agent forwards the event.
7. Wazuh evaluates the event against the custom detection rule.
8. A high-severity alert is generated for SOC investigation.

### Why this mapping?

Attackers use PowerShell to execute malicious commands and scripts directly on Windows systems. The use of the `-EncodedCommand` parameter is a common obfuscation technique that hides the original command from casual inspection while allowing PowerShell to execute it normally.
## Detection Logic
The detection monitors PowerShell process creation events for command-line arguments containing the `-EncodedCommand` or `-enc` parameter.

When detected, the event is classified as suspicious because attackers commonly encode PowerShell commands to bypass security monitoring, evade detection, and execute payloads in memory.

The detection relies on process creation telemetry generated by Sysmon (Event ID 1) or Windows Security Event ID 4688.
